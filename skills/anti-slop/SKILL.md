# Anti-slop review

Before you finish UI for a Deviecall venture, read `anti-slop.md` at the root of this repo and apply every rule. That file is the checklist. Do not substitute a shorter list from memory.

Then answer, in the work notes or the pull request:

- Which kit, and which token file.
- Where the paper, simulated, live, illustrative, or research-use label sits, if the screen can show that kind of data.
- Which rule in `anti-slop.md` was the closest call, and why the screen still passes it.

If a rule fails, change the UI. Do not waive a rule inside a kit brief. A kit may only get stricter.
